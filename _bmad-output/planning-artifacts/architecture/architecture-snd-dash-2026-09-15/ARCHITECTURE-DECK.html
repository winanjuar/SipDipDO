Inti: LEDGER

Tabel transaksi efektif append-only. Semua yang tampil — tabel kepemilikan, chart, Portion, Strength — adalah proyeksi turunannya. Koreksi = entry kompensasi, bukan edit.

Satu rumus, dua runtime

shared/domain — modul TS murni berisi seluruh rumus (Ceil, Shares, Strength, RTL, RKAP, distribusi laba). Dipakai server (otoritas) dan pulau pratinjau. Pratinjau tidak pernah berbeda hasil dari validasi.

0210 modul & arah dependensi

Panah selalu menuju LEDGER. Audit ditulis semua, dibaca tak seorang pun (kecuali COO). Email bereaksi setelah commit.

03Invariants — jantung kontrak (1/2)

Aturan yang tidak bisa dibaca ulang dari kode compliant — inilah yang mencegah dua tim membangun saling bertabrakan.

AD-1 · Satu penulis posisi

Hanya LEDGER menulis posisi, hanya lewat dua pintu finalisasi COO (+ import migrasi via API internal). Koreksi = entry kompensasi.

AD-2 · Finalisasi atomik

Satu transaksi DB: ledger + status (compare-and-set) + pembayaran + plotting RKAP + penyesuaian instant + audit. Row-lock fase RKAP — first-confirm wins.

AD-3 · Audit atomik append-only

Entry audit ditulis dalam transaksi yang sama dengan aksinya. Tanpa UPDATE/DELETE (DB grants). Aktor user | system.

AD-4 · Posisi terkopling ledger

Tabel posisi hanya diupdate di dalam transaksi append ledger — drift struktural mustahil; rekomputasi = alat rekonsiliasi.

AD-5 · Kepemilikan tabel mutlak

Satu tabel satu pemilik. Outbox email ditulis in-transaction, dikirim async + retry.

AD-6 · Satu rumus domain

Seluruh hitungan (termasuk perakitan input validasi Strength) di shared/domain — server & pratinjau identik by construction.

04Invariants — jantung kontrak (2/2)

AD-7 · Harga Terkunci

Snapshot harga saat submit = harga final. Re-validasi kondisi terkini saat finalisasi; referral = cek mekanis + penilaian manusia COO (cross-referral hari sama).

AD-8 · Akses dipaksa di server

3 tingkat (Calon Owner / Owner / COO) + matriks keterbukaan §4.8 di middleware server & route handler — pernah bukan hanya di klien. MFA OTP COO: hashed, single-use, TTL menit.

AD-9 · Operasional

Vercel + Supabase PG 17 (Singapore). Cron harian — batas hari dihitung Asia/Jakarta di endpoint. Backup harian/PITR + drill restore sebelum go-live.

AD-10 · Uang numeric-safe

Rupiah numeric(18,2), metrik integer, ratio presisi penuh → half-up 2 desimal saat sajikan. Rekap RUPS = snapshot imutabel + baris penyesuaian sisa pembulatan.

AD-11 · Siklus hidup owner satu penulis

Hanya IDENTITAS menulis status, via compare-and-set + re-validasi in-tx. "Pembelian Pertama efektif" = transaksi ledger pertama yang efektif (ditolak/ditarik/kedaluwarsa tak pernah menghasilkan baris ledger).

AD-12 · Dua postur, PWA data selalu daring

Satu basis kode, dua postur (lg); installed = viewport, bukan postur ketiga. PWA installable: cache hanya aset fingerprint + /offline; dokumen SSR & API no-store; update SW prompt; tanpa tulis luring.

Gerbang SM-1

Zero discrepancy — unit test wajib memakai contoh verifikasi PRD (66,67%; 861 saham; ratio 5/41/54; 4.340.000) + acceptance migrasi Grand Total 3.622 / 5.187 / 14.980.

06Topologi deployment

Dua layanan terkelola, nol server yang diurus sendiri. Muat di free/cheap tier.

Lingkungan: local (Supabase CLI/Docker) + production. Staging & ekstraksi layanan: deferred dengan alasan.

07Sengaja ditunda (Deferred)

Setengah dari kontrak adalah apa yang TIDAK diputuskan sekarang — masing-masing dengan alasan bisa menunggu.

  • Library chart — spesifikasi perilaku & visual final di EXPERIENCE/DESIGN; pilihan library (Chart.js vs ECharts) dijatuhkan saat scaffold.
  • Keputusan UX/UI — hidup di DESIGN.md & EXPERIENCE.md (final Sep 2026); spine merujuk tanpa menduplikasi.
  • PWA baca luring — ditolak Phase 1: data keuangan tak boleh tersaji usang; tulis luring melanggar AD-2.
  • Alur penjualan Phase 2 — ruang sudah disiapkan (ledger berorientasi transaksi, posisi bisa turun, koreksi kompensasi).
  • RLS PostgreSQL — otorisasi cukup di aplikasi untuk v1.
  • i18n — Bahasa Indonesia saja (publik luas bukan pengguna).
  • Staging environment — solo dev; menyusul bila tim bertambah.
