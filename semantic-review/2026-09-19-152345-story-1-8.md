# Story 1.8: Manajemen Owner oleh COO

Implements CRUD owner management for COO users: list, detail, create, and update operations via new API endpoints under `/api/admin/owners/`. UI components (OwnerPicker, OwnerEditDialog, OwnerAddDialog) power the `/admin/owners` page. The design follows the clean architecture spine with domain logic in `owner.service.ts`, validation in `owner.schemas.ts`, and thin API handlers delegating to the service layer. Status field changes are blocked per AD-11 — all status transitions remain domain-event-driven.

**Verdict**: APPROVED

## High-level view

The domain layer introduces `owner.service.ts` with four operations: `listOwners`, `getOwnerById`, `updateOwner`, and `createOwnerByCoo`. All mutations run inside a DB transaction that includes the audit write — satisfying AD-3 atomicity. Status and email immutability are enforced at two levels: Zod schemas via `.strict()` reject unknown fields, and API handlers explicitly check for forbidden fields before parsing.

Authorization follows the AD-8 pattern: each handler retrieves the session email, resolves to an owner record, then verifies active COO tenure via `findActiveCooTenure(db, ownerId, new Date())`. Non-COO users receive 403.

The module index (`server/domain/identity/index.ts`) exports all new symbols. API handlers import through this index.

## Status protection enforcement (AD-11)

The update schema omits `status` and uses `.strict()`. The PUT handler also explicitly checks for `status` in `rawBody` before parsing:

```typescript
if (rawBody && typeof rawBody === 'object' && 'status' in rawBody) {
  return sendApiError(event, HTTP_STATUS.badRequest, {
    code: OWNER_VALIDATION_ERRORS.STATUS_CHANGE_FORBIDDEN,
    ...
  })
}
```

Same pattern blocks `email` updates.

## Audit trail atomicity (AD-3)

Both `updateOwner` and `createOwnerByCoo` call `writeAuditEntry(tx, ...)` inside their transaction. Update only writes audit if there are actual changes (`Object.keys(changes).length > 0`).

## Future test considerations

Concurrent updates (two COOs editing same owner), emergency contact partial updates.
